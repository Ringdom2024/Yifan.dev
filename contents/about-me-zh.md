我最早判断一个项目是否完成，标准很简单：代码能跑，页面能开。

后来项目变复杂了。程序在我的电脑上运行得很好，换一台机器却开始报错；模型给出一串看起来不错的指标，预测图里却漏掉了最关键的小目标；几个模块各自都能演示，真正接在一起时却总在接口、路径或音频格式上中断。那时我才慢慢明白，运行成功只是起点。

我叫王一凡，就读于山东女子学院数据科学与大数据技术专业。现在的我仍是一名学习者，但比起罗列会用多少工具，我更想回答另一个问题：我能不能把这些工具连起来，解决一个具体问题？

## 我的方向不是一次选出来的

我的学习轨迹看上去有些分散。写过 Java Web 和 MySQL，做过网络数据采集，训练过 YOLO，也尝试把 RAG、本地大模型、语音识别和数字人放进同一套系统。

这些经历后来指向了同一个兴趣：让数据、模型和软件工程真正发生连接。

一个数据项目不该只停在清洗表格，一个视觉实验也不该只停在运行官方命令。数据从哪里来，怎样存储，模型为什么犯错，接口如何传递结果，页面怎样反馈状态，系统能否部署，这些环节共同决定了一个想法能不能落地。

## 报错构成了另一张课程表

课堂给了我基础，报错则不断提醒我还有哪些地方没有真正理解。

我遇到过 CUDA 与 PyTorch 版本不匹配，也处理过 Tomcat 兼容、数据库连接、Nginx 路由、依赖缺失和文件编码问题。有些错误只需要改一行配置，有些问题却要沿着日志一点点缩小范围。

它们让我形成了几个习惯：

- 先稳定复现问题，再开始修改
- 一次只验证一个猜想，不同时乱改多个地方
- 为关键模块保留日志、输入和输出样例
- 记录环境、版本和最终有效的解决方法
- 不把“偶然跑通”当作已经掌握

这些习惯看起来不耀眼，却比某个短暂成功的截图更能帮助我走得远一点。

## 我希望项目能够被别人接住

现在我会更在意目录结构、依赖文件、环境变量、数据库脚本、启动命令和异常提示。如果另一个人拿到代码后完全不知道如何开始，那么项目还没有真正完成。

我正在学习把“我能运行”变成“别人也能理解、复现和继续修改”。这也是我搭建这个网站的原因之一。它不是一张静止的简历，而是一个持续更新的工作台：项目做到了哪一步，哪些判断有效，哪些地方仍然不成熟，都可以留下来。

## 接下来，我想继续把问题做深

目前我更关注计算机视觉、人工智能应用、数据采集与分析，以及 Web 系统部署。我希望继续研究交通标志等小目标检测，也想把知识检索、本地模型、语音和交互界面组合得更自然。

与此同时，我还需要补强数据结构、算法、计算机网络、数据库原理、数学基础和英文资料阅读。承认这些不足并不令人沮丧，反而让我知道下一段路应该往哪里走。

我还没有一个漂亮的终点答案。但我越来越确定，自己喜欢的不是把技术名词堆在一起，而是把一个混乱的问题逐步拆开，直到它真的能够运行、解释和交付。
